# Dipin Dawadi Portfolio — Control System DNA

## Approved visual reference

The approved direction is the black ERP-security identity graphic built around Dipin Dawadi’s name and a four-stage authorization path: **Request → Authenticate → Authorize → Verified**.

## Visual thesis

**Enterprise access control system.** The interface should feel like a precise, premium control blueprint: a warm mineral-gray field, dark ink, restrained copper pathways, and a single olive verified state. It must remain professional rather than drifting into vintage parchment, neon hacker, or science-fiction UI.

## Principles

1. Strong identity first: name, role, and specializations dominate the first viewport.
2. Copper communicates an active path or decision; green is reserved for verified states.
3. Technical grids, circuits, and logs stay quiet enough that typography remains primary.
4. Motion explains the authorization sequence and never hijacks scrolling.
5. Completed work, current responsibility, and future assignments remain explicitly separated.
6. Mobile, keyboard, reduced-motion, and no-JavaScript experiences stay understandable.

### Geometry

- Content width: `1280px`
- One-pixel copper rules and pathways
- Circular nodes only for authorization states
- Mostly square, precise surfaces with minimal rounding

## Motion identity

- Quick: `140ms`
- Standard: `260ms`
- Narrative: `620ms`
- Signature easing: `cubic-bezier(.2,.8,.2,1)` / GSAP `power3.out`
- Hero sequence: masked identity reveal → circuit draw → sequential nodes → routed signal → verified state.
- Ambient layer: slow grid drift, restrained scanner sweep, and live signal travel. No decorative card floating.
- Scroll layer: section headlines rise in sequence, evidence rails draw vertically, counters resolve once, and portrait/project media reveal through directional masks.
- Interaction layer: authorization progress follows the selected control; its inspector scans once on state change. Primary buttons use a small magnetic response on fine pointers.
- Navigation layer: a two-part control-screen wipe bridges internal pages and a copper trace reports reading progress.
- Reduced motion removes transforms, pulses, wipes, counters, and smooth scrolling while retaining every state and all content.

## Page hierarchy

### Home

1. Identity plus authorization path
2. Verified scope
3. Interactive access-control explanation
4. One completed-work record
5. Current assignment separated from upcoming scope
6. Projects, capabilities, education, credentials, and contact

### Experience

Security roles receive full control-record treatment. Upcoming GRC consolidation is explicitly labeled “Not yet started.” Supporting engineering, data, research, and leadership work uses a compact archive.

### Projects

Projects use dark media records, copper metadata, and restrained technical transitions to demonstrate transferable product, automation, and analytics ability.
